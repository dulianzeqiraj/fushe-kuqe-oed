# Information-geometric monitoring network design for the Fushë-Kuqe alluvial aquifer

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.22726726.svg)](https://doi.org/10.5281/zenodo.22726726)

Code and data for the manuscript

> Zeqiraj, D. *What is a nitrate measurement worth? Fisher information and
> goal-oriented monitoring network design in alluvial aquifers.*

Everything reported in the paper is produced by one command. No figure, table or
number in the manuscript comes from anywhere else.

```bash
cd code
matlab -batch "fk_prepare_data; run_all; fk_figures"
matlab -batch "fk_fill_manuscript; fk_build_docx; fk_verify_docx"
```

Everything is MATLAB. There is no Python, no pandoc and no external converter
in the chain: the data are read from the workbook with `readtable`, the
manuscript is assembled from `results.json`, and the .docx is written as
WordprocessingML with the equations as real Office MathML, so they stay
editable in Word rather than becoming pictures.

The run writes `results/results.json`, which is the only file the manuscript
quotes from, and `results/run_all.mat` with the complete state. Figures land in
`figures/`; the submission documents land in `manuscript/`.

## What is in here

```
code/     the pipeline and the document toolchain, all MATLAB
data/     flat CSVs extracted from the sources below, nothing altered
results/  results.json and run_all.mat, both regenerated by run_all
figures/  the figures of the manuscript, regenerated by fk_figures
manuscript/  the source, the template, and the built submission documents
```

| `fk_prepare_data.m` | copies the field workbook and the USGS file into flat CSVs |

| `fk_load_data.m` | reads the tables and prints the data inventory |
| `fk_predictability.m` | asks whether the nitrate field is predictable at all |
| `fk_build_grid.m` | flow-aligned grid over the aquifer polygon |
| `fk_prior_field.m` | porosity prior, vulnerability field, Karhunen-Loève basis |
| `fk_forward.m` | transient transport operator |
| `fk_calibrate.m` | estimates the loading field and its onset time |
| `fk_sensitivity.m` | exact discrete Jacobian and the Fisher information |
| `fk_design.m` | D-optimal and goal-oriented placement, horizon, equivalence |
| `oed_local.m` | the same two criteria under a local observation operator |
| `fk_particles.m` | implicit sampling against SIR, natural versus Euclidean descent |
| `mrva_replicate.m` | independent replication on the USGS MRVA dataset |
| `fk_sweep.m` | every `[ASSUM]` constant varied, one at a time |
| `fk_write_results.m` | writes `results/results.json` |
| `fk_figures.m` | the figures |
| `fk_fill_manuscript.m` | puts the run's numbers into the manuscript, and refuses if one is missing |

## Data sources

The repository carries derived flat files. The primary sources are:

1. **Fushë-Kuqe field workbook** (`Fushe_Kuqe_All_Data.xlsx`). 180 monitoring
   points with Gauss-Krüger coordinates (Krasovsky 1940, zone 4) and DRASTIC
   indices; 43 of them with a pumping-test hydraulic conductivity, depth to
   water, lithological description, soil and vadose-zone class; 31 with a
   nitrate measurement; a 3411-vertex aquifer boundary. Compiled by the author
   from Albanian Geological Survey and IGJEUM records.
2. **Seawater-intrusion context**, transcribed into the same workbook from
   Cenameri, S., Beqiraj, A. (2016), *Assessment of seawater intrusion in Fushe
   Kuqe aquifer, Albania*, Bulletin of the Geological Society of Greece 50(2),
   665. <https://doi.org/10.12681/bgsg.11772>
3. **Mississippi River Valley alluvial aquifer**, 44 wells with slug-test
   hydraulic conductivity and transmissivity, from Pugh, A.L., *Hydraulic
   conductivity and transmissivity estimates from slug tests in wells within the
   Mississippi Alluvial Plain, Arkansas and Mississippi, 2020*, U.S. Geological
   Survey Scientific Investigations Report 2023-5101.
   <https://doi.org/10.3133/sir20235101> The DRASTIC ratings attached to those
   wells were assigned by the author; the code recomputes every DRASTIC index
   from its seven ratings and stops if any of them fails to reproduce.

The porosity prior is not re-derived here. It is taken from the Dual-Pathway
fusion already published for this aquifer:

- Zeqiraj, D., Beqiraj, A. (2026). Adaptive stacked ensemble fusion: Bayesian
  porosity inference in alluvial aquifers when the errors are not independent.
  *Journal of Contaminant Hydrology* 283, 105086.
  <https://doi.org/10.1016/j.jconhyd.2026.105086>
- Zeqiraj, D., Beqiraj, A., Jahja, A., Seitaj, B., Progni, F., Zeqo, E. (2026).
  Physical, biophysical, and chemical mechanisms of bidirectional coupling
  between DRASTIC vulnerability assessment and numerical transport modeling in
  heterogeneous aquifer systems. *Journal of Hazardous Materials Advances* 23,
  101261. <https://doi.org/10.1016/j.hazadv.2026.101261>

## Requirements

MATLAB R2020b or later and the Statistics and Machine Learning Toolbox, which
is used for `corr` and `fcdf`. Nothing else: no Python, no pandoc, no Report
Generator. The document writer uses the JVM that ships with MATLAB for zip and
digest work. The run takes on the order of half an hour on a desktop machine;
the expensive parts are the posterior sampling and the dispersivity sweep, each
of which rebuilds the Jacobian.

`manuscript/template.docx` carries the styles, numbering and page setup that
the document writer fills. It is committed so that a reader need not rebuild
it; `fk_make_template.m` is how it was made.

## Reproducibility

`cfg.seed` fixes every random draw. The Jacobian is the exact derivative of the
discrete system rather than a finite difference, and `fk_sensitivity` checks it
against finite differences at three step sizes and reports the convergence
order. The DRASTIC indices of the MRVA wells are recomputed from their ratings
on every run. `fk_check_omml` converts every equation in the paper and fails
rather than dropping one. `fk_verify_docx` checks that nothing but the listings
follows the references, that no placeholder, em dash, control character or
stray dollar sign survived, and that every listing matches the file on disk.
`results.json` carries the MATLAB version, the run date and the wall-clock
time.
